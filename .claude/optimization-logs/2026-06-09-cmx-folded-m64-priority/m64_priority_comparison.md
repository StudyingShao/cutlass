# CMX folded weight-scale layout: M64-priority sweep

Date: 2026-06-09

## Goal

Evaluate an M64-priority folded weight-scale layout for the fused E8M0 pre-MMA scaling path. The layout keeps scale preprocessing independent of runtime Ktile while intentionally protecting TileM=64 configs: one M64 lane owns contiguous K128 blocks. TileM=64 uses one contiguous bulk copy; TileM=128 uses two; TileM=256 uses four. This matches the current preference to protect TileM=64 and accept possible TileM=256 cost.

## Command context

- GPU: `CUDA_VISIBLE_DEVICES=3 CLOCK_GPU_INDEX=3`
- Binaries: `69_hopper_mxfp4_fp8_grouped_gemm_fused_e8m0_token_scale_k{128,256,512}`
- Options: `--warmup=20 --iterations=300 --split_timing=true --compare=true --explore=true`
- Shapes: `E256_M24_N512_K4096`, `E32_M128_N4096_K4096`

## Summary

- M64-priority fixes the worst K128 outliers introduced by the 2x2 layout and improves the key E256 K512 best from the latest 4x1 sweep, but it still does not fully recover the old original K512 best on E256.
- The best E256 result is `145.750 us` with `PP Shape<_2,_1,_1> Tile<_64,_32,_512> S=6`, compared with original `143.119 us`, latest 4x1 `148.414 us`, and 2x2 `146.837 us`.
- The best E32 result is `507.362 us` with `PP Shape<_1,_2,_1> Tile<_64,_64,_512> S=4`, compared with original `508.288 us`, latest 4x1 `507.544 us`, and 2x2 `506.890 us`.
- Remaining >5% regressions are dominated by configs that are not best for these two shapes, especially TileM=128/256 and very skinny TileN cases. This is consistent with the M64-priority tradeoff.

Raw sweep logs and the full per-config CSV were kept as local artifacts and
are not part of the staged documentation.
